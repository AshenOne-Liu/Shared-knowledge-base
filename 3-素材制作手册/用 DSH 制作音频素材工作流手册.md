# 用 DSH 制作音频素材工作流手册

## 插件

> DSH 生态里确实有专注音频的插件，而且刚好覆盖了“程序化合成”和“AI 生成”两种不同的路径。针对你海风、下雨这类白噪音的需求，下面这几款很值得对比。

### 🌧️ `dsh-adhd-noise`：实时合成，零素材、零网络

如果你想要的是**“打开就能听、不依赖任何外部素材或网络”**的确定性方案，这款插件最直接。

它完全在浏览器里通过 **Web Audio API 实时合成**声音，仓库里没有任何音频文件，也不发起网络请求。它提供五种声音：**白噪声、粉红噪声、棕色噪声、雨声、风扇声**。

其中“雨声”的合成方式比较讲究：以粉红噪声为底，叠加低频“body 层”、6 kHz 的水雾 shimmer，以及密度起伏的雨滴细节。虽然它没有直接内置“海风”，但白/粉/棕噪本身就是海浪声的常见合成基底，你可以把它当作一个可控的起点。

**交互方式**也很轻量：安装后，输入框下方会出现一个小胶囊，点击即可播放；展开后是一张带**真实波形声球**的浮层卡片，并提供 15–90 分钟的淡出定时器。它完全在浏览器端运行，不需要 API Key。

**安装命令**：

```bash
dsh plugin --profile desktop add "git+https://github.com/tommy00748-tech/dsh-adhd-noise.git"
```

### 🎛️ `dsh-audiogen`：AI 音效生成，更接近“定制”

如果你希望**通过描述来“生成”海风、下雨等特定音效**，而不是从固定预设中选择，这款插件是更合适的工具。

它把 DSH 变成了一个小型音频工作室，支持**音效生成（SFX）** 模式，可以从侧边栏或直接让 Agent 调用。它接入了多家供应商（OpenAI 兼容接口、ElevenLabs、Stability AI 等），意味着你可以用自然语言提示词去请求“海风、下雨、远处雷声”这类具体的环境音效。

代价是它**需要配置外部 API 通道**，并非开箱即用的零依赖方案。但如果你需要的场景非常具体（比如特定强度、特定氛围的海浪声），这种可提示、可迭代的生成方式会比固定合成音色灵活得多。

**使用入口**：安装后，在 DSH 的 **设置 → 插件 → AI Audio** 中添加通道，然后在工作室左侧的模式栏选择 **SFX** 即可开始生成。

### 📁 `dsh-ambient`：如果“下载现成氛围音”也符合你的定义

`dsh-ambient` 的思路稍有不同：它是一个**目录驱动的白噪音播放器**。你点击“执行下载”后，后台 AI 会从 **Wikimedia Commons** 自动下载 CC0/PD/CC-BY 许可的氛围音，并按场景分类存放。你也可以自己往对应文件夹里放音频文件，场景完全由文件夹结构决定。

它内置了顺序、随机、单曲循环、间歇四种播放模式，以及定时关闭功能。如果你的需求本质是“**有一个稳定的雨声/海浪声在背景里循环**”，而不太在意声音是“实时生成”还是“下载来的现成文件”，这款插件用起来会很顺手。

**安装命令**：

```bash
dsh plugin --profile web add @weibaohui/dsh-ambient -w
```

### 💎 怎么选？

| 插件 | 核心机制 | “海风/下雨”能力 | 依赖与门槛 | 适合谁 |
| --- | --- | --- | --- | --- |
| **`dsh-adhd-noise`** | Web Audio 实时合成 | 内置雨声、风扇；白/粉/棕噪可作海浪基底 | **零依赖**，无需 API Key、无网络 | 想要开箱即用、零配置、确定可复现的声景 |
| **`dsh-audiogen`** | 多供应商 AI 音效生成 | 可通过提示词**定制生成**海风、下雨等 | 需配置外部音频 API 通道 | 需要特定氛围、愿意为灵活性付出配置成本 |
| **`dsh-ambient`** | 目录驱动 + 后台下载 | 可下载雨声、溪流、篝火等现成氛围音 | 依赖网络下载；声音是“获取”而非“生成” | 想快速拥有一个可管理的本地氛围音库 |

如果你追求**最轻量、最确定**的体验，优先试 `dsh-adhd-noise`，它和 DSH 本身的设计哲学（零运行时依赖、浏览器端合成）一脉相承。如果你需要**真正“生成”出符合特定描述的海风**，再考虑 `dsh-audiogen` 的 SFX 模式。

## 商用合规性说明

两款插件可以商用的前提不同：`dsh-adhd-noise` 的音频是你“合成”出来的，商用障碍很小；`dsh-ambient` 的音频是“下载”来的，**必须逐文件核对许可证**，能否商用取决于具体文件的许可类型。

---

### 🎛️ `dsh-adhd-noise`：合成音频，商用基本无障碍

这款插件的代码采用 **MIT 许可证**，授予的使用权限非常宽松，包括**商业使用、修改、分发，甚至出售**，只需保留原版权声明和许可声明。

更关键的是，它的声音是**在浏览器里实时程序化合成的**，插件本身“不下载任何音频文件，不占用网络”。这意味着输出中**不包含任何第三方的受版权保护的录音素材**，你听到的雨声、粉红噪声等，是由算法直接生成的声波，而不是从某个版权音乐库里“拿来”的。

**商用结论**：用 `dsh-adhd-noise` 合成的音频**可以用于商业项目**。建议在产品的第三方声明或 credits 中保留一句“Noise synthesis powered by dsh-adhd-noise (MIT License)”，这是对 MIT 许可证版权声明的尊重，也能避免任何潜在的合规争议。

---

### 📁 `dsh-ambient`：下载的音频，需要“一文件一议”

`dsh-ambient` 插件本身的代码同样是 **MIT 许可证**，但这**不覆盖它下载的音频文件**。插件从 **Wikimedia Commons** 抓取音频，而 Commons 上每一条音频都带着**独立的许可证**，插件作者无法替这些文件统一授权。

插件会按“**CC0 / PD > CC BY > CC BY-SA**”的优先级筛选下载，并生成 `INDEX.md` 和 `ATTRIBUTION.txt` 来记录来源和许可证信息。不同许可证的商用条件如下：

| 许可证类型 | 能否商用？ | 你需要做什么？ |
|---|---|---|
| **CC0 / Public Domain（PD）** | ✅ 可以 | 无需署名，可直接使用 |
| **CC BY** | ✅ 可以 | **必须署名**：注明作者、来源（Wikimedia Commons 链接）和许可证 |
| **CC BY-SA** | ✅ 可以商用 | 必须署名，且**衍生作品需以相同许可证共享**——这一点对商业闭源产品可能构成限制 |

Wikimedia Commons 本身**不接受“禁止商业使用”（NC）的素材**，所以你通过这个插件下载到的音频，至少在法律上**不排斥商业用途**。但“可以商用”不等于“你可以忽略署名”。

**商用结论**：`dsh-ambient` 下载的音频**可以用于商业项目，但必须逐文件检查许可证，并严格履行署名义务**。具体操作是：打开插件库目录下的 `ATTRIBUTION.txt`，找到你实际要用的那个文件对应的条目，确认其许可证类型，然后在你的产品中按要求署名。如果许可证是 CC BY-SA，还需要评估你能否接受“相同方式共享”的传染性条款。

---

### ✅ 商用前快速检查清单

**对于 `dsh-adhd-noise`：**
1. 确认你用的是插件**实时合成输出**，而非手动放入的第三方音频。
2. 在 credits 中保留 MIT 许可证声明。

**对于 `dsh-ambient`：**
1. 定位你实际要商用的**那一个音频文件**。
2. 在 `ATTRIBUTION.txt` 中查看它的许可证类型。
3. **CC0/PD**：直接使用。**CC BY**：准备署名文本。**CC BY-SA**：确认你能接受“相同方式共享”条款，否则换用 CC BY 或 CC0 的替代文件。
4. 将署名信息放入产品的 credits / 第三方声明中，并保留到源文件的链接。

## 流程手册

以下《DSH 音频素材工作手册》沿用像素手册的结构逻辑，但针对音频素材的特殊性做了调整：**音频没有“像素网格”可以肉眼校验，取而代之的是“技术参数”与“法律许可”两条验收线**。手册把“自己合成”和“下载音频”拆成两条并行的工作流，并在需要合并判断的地方给出统一的决策逻辑。

### 一、动手之前：先选路径，再锁规格

音频素材的返工来源比像素更隐蔽——**像素画错了肉眼可见，音频“不对”往往要等到放进场景里才暴露**。动手之前，先做一个关键决策：**这条素材应该“合成”还是“获取”？**

**选“自己合成”，当以下条件至少满足两项：**
- 需要**无缝循环**（场景白噪音、环境底噪）；
- 需要**参数可复现**（同一参数必然产出同一声音，便于版本管理）；
- 场景属于**纹理型声景**（白/粉/棕噪、雨声、风声、风扇、火焰），而非有明确“事件感”的音效；
- 希望**零外部依赖**，不配置 API、不依赖网络。

**选“下载/获取”，当以下条件至少满足一项：**
- 需要**真实录音质感**（远处雷声、特定鸟鸣、城市街道）；
- 场景需要**语义明确的一次性音效**（开门、爆炸、UI 点击）；
- 团队没有音频制作能力，但能接受**逐文件核对许可**。

选定路径后，锁定规格。音频的“规格”不是尺寸和调色板，而是以下五项：

| 规格项 | 需要写死的内容 | 为什么重要 |
|---|---|---|
| **声道** | 单声道 / 立体声 | 立体声在耳机下的空间感更好，但文件体积和合成复杂度更高 |
| **采样率 / 位深** | 44.1 kHz / 48 kHz，16-bit / 24-bit | 与目标引擎或视频工程保持一致，避免导出后二次转换 |
| **时长与循环方式** | 循环底噪（30s / 60s 无缝）/ 一次性音效（精确到 0.1s） | 循环素材的首尾衔接是最大的技术陷阱 |
| **响度基准** | 例如 -16 LUFS（移动端）/ -14 LUFS（流媒体） | 多个素材混合时响度不一致会导致频繁手动调音量 |
| **命名与存放** | `场景_变体_时长.扩展名`，按 `SFX / ambience / music` 分目录 | 素材库超过 20 个文件后，命名混乱的代价会急剧上升 |

**实操建议**：在对话开头用一小段话把路径和规格说死，例如“这条做合成路径，立体声，44.1 kHz / 16-bit，60 秒无缝循环，-16 LUFS，命名为 `rain_loop_60s.wav`，存到 ambience/ 目录”。


### 二、路径 A：自己合成音频（以 `dsh-adhd-noise` 为核心）

#### 2.1 先理解“合成”意味着什么

`dsh-adhd-noise` 的声音**全部由 Web Audio API 在浏览器中实时生成**，仓库里没有任何音频文件，也不发起网络请求。这意味着你拿到的不是“一个下载好的雨声文件”，而是“一套生成雨声的算法”。这对工作流有两个直接影响：

第一，**输出质量取决于合成参数，而非素材来源**。雨声的合成路径是“粉红底噪 + 低频 body 层 + 6 kHz 水雾 shimmer + 密度起伏的雨滴（含偶尔的大雨滴）”，雨声和风扇还使用了去相关的立体声缓冲区来提升耳机下的声像宽度。如果听起来“不够像雨”，问题不在“素材不好”，而在参数是否需要调整。

第二，**循环无缝性是合成路径的天然优势，但不是自动保证**。插件的所有调制频率都取 8 秒循环的整数周期，目的是让循环点无爆音。但你导出的片段如果是从任意时间点截取的，循环点仍然可能落在非整数周期上——**导出时必须显式指定循环边界**，而不是“录一段然后首尾拼接”。

#### 2.2 合成路径的工作流

**第 1 步：从最接近的合成音色起步，不追求一步到位。** 插件提供五种声音：白噪声、粉红噪声、棕色噪声、雨声、风扇声。海风、火焰、溪流等需求没有直接对应的预设，但**粉红噪声和棕色噪声是海浪声和火焰底噪的常见合成基底**——粉红噪声的能量分布更接近自然界的宽带噪声，棕色噪声的低频更重，适合做“远处海浪的闷响层”。

**第 2 步：在插件内试听，确认“基底方向”正确，再导出。** 安装 `dsh-adhd-noise` 后，对话输入框下方会出现一个小胶囊，点击即可播放；展开后是一张带真实波形声球的声景卡片，可以在五种声音之间切换，并设置 15–90 分钟的定时淡出。这一步的目标不是“做出最终成品”，而是**判断这个合成音色是否值得作为进一步加工的基础**。如果连方向都不对（比如你想要的是“海浪拍岸”的节奏感，而粉红噪声只有平稳的沙沙声），就换基底，不要在错误的基础上叠加参数。

**第 3 步：导出时锁定循环参数。** 合成路径的导出不是“按一下录音键”，而是**在导出时显式指定循环片段**。需要确认三件事：导出的时长是否是合成调制周期的整数倍；首尾采样点是否在过零点附近（避免循环处的咔嗒声）；导出格式是否与目标引擎一致（WAV 无损，OGG/MP3 用于体积敏感场景，但要注意编码器在循环点引入的padding）。

**第 4 步：如果需要“事件感”更强的音效，切换到生成路径。** `dsh-adhd-noise` 的能力边界是**纹理型声景**，不是“一次性音效生成器”。如果你需要的是“火焰中偶尔的爆裂声”“远处一声闷雷”，它不直接提供这类离散事件。此时应该切换到 **`dsh-audiogen` 的 SFX 模式**：它支持通过提示词生成音效，接入 OpenAI 兼容接口、ElevenLabs、Stability AI 等多家供应商，生成结果可以按 `SFX / ambience / music / TTS` 分目录入库，并保留完整的溯源信息（渠道、模型、提示词、参数快照）。代价是需要先在 **设置 → 插件 → AI Audio** 中配置 API 通道。

**合成路径的适用判断**：如果需求可以用一句话描述为“某种持续的、没有明确起止事件的声音”，优先合成；如果需求包含“一次”“一声”“突然”这类离散语义，合成路径会让步给生成路径。


### 三、路径 B：下载/获取音频（以 `dsh-ambient` 为核心）

#### 3.1 先理解“下载”意味着什么

`dsh-ambient` 是一个**目录驱动的白噪音播放器**。场景完全由音频根目录下的子文件夹决定——有什么文件夹就有什么场景，有什么音频就播什么，没有预制清单。它的核心工作流是：在设置页点“执行下载”，后台 AI 从 **Wikimedia Commons** 按 CC0 / PD / CC BY 许可**分门别类**下载音频到对应场景文件夹，同时更新 `INDEX.md` 和 `ATTRIBUTION.txt`。

这意味着下载路径与合成路径有本质区别：**你拿到的不是“算法”，而是“别人已经录好的、带着特定许可证的文件”** 。工作流的重心因此从“调参”转移到“**筛选与合规**”上。

#### 3.2 下载路径的工作流

**第 1 步：先建场景目录，再执行下载。** 因为场景完全由目录决定，最可控的做法是**手动创建你需要的场景文件夹**（如 `rain/`、`ocean/`、`forest/`），然后在设置页执行下载。AI 会按许可优先级（CC0/PD > CC BY）下载音频到对应文件夹，并在 `ATTRIBUTION.txt` 中记录来源和许可信息。也可以跳过 AI 下载，直接往文件夹里放自己的音频文件，点击“扫描”即可入库。

**第 2 步：下载完成后，逐文件打开 `ATTRIBUTION.txt`，不要跳过这一步。** 这是下载路径最关键的环节，也是它与合成路径最大的区别。`dsh-ambient` 的 MIT 代码许可证**不覆盖它下载的音频文件**；每个音频文件带着独立的许可证，商用条件不同：

| 许可证 | 商用 | 你需要做什么 |
|---|---|---|
| **CC0 / PD** | ✅ | 无需署名，直接使用 |
| **CC BY** | ✅ | **必须署名**：作者、来源（Commons 链接）、许可证 |
| **CC BY-SA** | ✅ | 必须署名，且**衍生作品需以相同许可证共享**——对闭源商业产品可能构成限制 |

Wikimedia Commons 本身不接受“禁止商业使用”（NC）的素材，所以通过这个插件下载到的音频在法律上**不排斥商用**，但“可以商用”不等于“可以忽略署名”。

**第 3 步：只播放和导出你**已经核对过许可的**文件。** `dsh-ambient` 支持顺序循环、随机、单曲循环、间歇四种播放模式，以及收藏和“只播收藏”功能。建议的工作习惯是：下载完成后，先逐文件核对 `ATTRIBUTION.txt`，将许可清晰的（CC0/PD 和可接受署名条件的 CC BY）标记为收藏，然后**只播收藏**进行试听筛选。未核对许可的文件不要进入最终素材清单。

**第 4 步：导出/使用时，把署名信息一并带走。** 下载路径的“导出”不是格式转换，而是**合规交付**。如果最终素材进入商业项目，`ATTRIBUTION.txt` 中对应条目的署名文本必须出现在产品的 credits 或第三方声明中。建议在素材库中为每个最终选用的文件建立一个 `文件名_license.txt` 的伴随文件，记录许可证类型和完整署名文本，避免上线前遗漏。


### 四、两条路径的合并决策与共享原则

#### 4.1 什么时候需要“混合路径”

一个场景的声景很少由单一素材构成。典型情况是：**底层用合成路径做无缝循环的“底噪”（雨声、风声、海浪基底），上层用下载路径叠 1–2 个真实录音的“点缀层”（远处雷声、鸟鸣、水滴）** 。这种混合是合理的，但需要额外注意两点：

- **响度对齐**：合成素材和下载素材的原始响度大概率不一致。在混音前，把底噪和点缀层都对齐到同一个响度基准（如 -16 LUFS），否则会出现“底噪刚好，雷声炸耳”的情况。
- **许可隔离**：混合路径中，合成部分没有第三方许可约束（MIT 插件代码 + 算法输出），下载部分有。**署名义务只针对下载的那一层**，不要把合成素材也拉进 `ATTRIBUTION.txt` 的署名范围，也不要用合成素材的“无约束”去掩盖下载素材的署名要求。

#### 4.2 共享的单变量迭代原则

无论哪条路径，**一轮只改一个变量**。合成路径中，“同时改基底音色 + 循环时长 + 音量”会让问题无法定位；下载路径中，“同时换场景 + 换播放模式 + 改许可筛选条件”会让合规状态变得不可追踪。推荐的节奏：

- **合成路径**：基底音色 → 循环边界 → 声道/空间感 → 响度 → 导出格式。
- **下载路径**：场景目录结构 → 下载批次 → 许可核对 → 收藏筛选 → 导出/署名。

#### 4.3 导出前验收：两条路径分别打勾

**合成路径验收清单：**

- [ ] 循环点**无咔嗒声**：首尾采样在过零点附近，或调制周期为整数倍。
- [ ] 声道与目标一致（立体声文件在单声道引擎中不应产生相位抵消）。
- [ ] 响度对齐到锁定基准。
- [ ] 如果使用 `dsh-adhd-noise` 的合成输出，在 credits 中保留一句 `Noise synthesis powered by dsh-adhd-noise (MIT License)`。
- [ ] 如果是 `dsh-audiogen` 生成的 SFX，确认资源库中保留了溯源快照（渠道、模型、提示词），以便复现或替换。

**下载路径验收清单：**

- [ ] 每一个最终选用的文件，其许可证类型已在 `ATTRIBUTION.txt` 中确认。
- [ ] CC BY 文件的署名文本完整（作者 + 来源链接 + 许可证名称）。
- [ ] CC BY-SA 文件已评估“相同方式共享”条款是否与产品分发方式兼容；如不兼容，换用 CC0/PD 或 CC BY 的替代文件。
- [ ] `ATTRIBUTION.txt` 的条目与实际使用的文件一一对应，没有“下载了但没用”的文件混入署名清单，也没有“用了但漏记”的文件。
- [ ] 如果音频需要进入视频/游戏工程，确认文件格式（WAV/OGG/MP3）与引擎兼容，且编码后的循环点没有引入额外 padding。

#### 4.4 一个贯穿两条路径的原则

合成路径的确定性来自**算法**：同样的参数必然产出同样的声音。下载路径的确定性来自**记录**：每一个文件的来源和许可都必须可追溯。两者共同的要求是：**不要让“听起来差不多”替代“技术上说得清”** 。合成素材要说得清循环参数和响度基准，下载素材要说得清许可证和署名文本。音频素材的返工成本往往不在“做”的阶段，而在“上线后才发现不能用”的阶段——验收清单的意义，就是在那个阶段之前把问题拦住。
