**Fantety/dsh-pixel-studio**
<https://github.com/Fantety/dsh-pixel-studio>

## 流程手册

### 精简说明（还需补充）

1. **先小后大**：先让 Agent 出 16×16 或 32×32 草稿，确认轮廓和配色，再放大精修。
2. **先静后动**：静态关键帧确认后再做动画，避免动画返工。
3. **每次只改一个变量**：尺寸、调色板、光照、动作分开提，Agent 更容易精准执行。
4. **导出前加验收句**：> 检查画布尺寸、透明背景、调色板数量、帧数和锚点是否符合上述要求，不符合则先修正再导出。

### 一、动手之前：先锁定“不可变规格”

像素素材返工的最大来源，往往不是画得不好，而是**规格在中途变了**。开始第一笔之前，先把下面这几项写下来，作为整个制作过程的“锁”：

**画布尺寸**、**调色板（名称或色数上限）** 、**锚点位置**（角色通常是“底部中心”，道具是“中心”）、**帧率与循环方式**（循环 / 单次）、**导出格式**（PNG / GIF / 精灵表 + JSON）。

`pixel-asset-master-skills` 的工作流框架中有一个核心文件叫 `spec_lock.md`，专门用来记录画布尺寸、调色板、风格、色数上限和禁止的渲染方式。Sprite Sheet Maker 的工作流也强调：**在画帧之前，先定好单帧尺寸、动作列表、播放速度、锚点和目标引擎**。DSH 的像素插件在执行前同样会校验尺寸、网格、调色板、帧时序和输出限制，规格越明确，Agent 的生成越稳定。

**实操建议**：在对话开头用一小段话把规格说死，例如“全程固定 32×32、PICO-8 调色板、底部中心锚点、8fps、透明背景”，后续每次迭代都默认沿用，不在中途改动。

---

### 二、先小后大：草稿阶段不追求完成度

**原则**：第一版只用最小尺寸（16×16 或 32×32）解决三个问题——**轮廓是否可读、配色是否成立、主体是否被认出**。细节、阴影、高光、特效全部留到放大阶段再加。

DSH 的像素插件内置了 12 个 16×16 模板（史莱姆、猫、机器人、药水、剑、心、幽灵、星、金币、树、蘑菇、水晶），可以直接作为“小稿”的起点，省去从零勾勒外轮廓的时间。KongChengZhi 版本的 CLI 工作流也遵循“打形 → 底色 → 阴影 → 高光”的分步顺序，第一笔永远是打形，而不是直接画细节。

**草稿阶段的验收标准**：把画面缩放到实际游戏尺寸（1×），眯眼看 3 秒，能认出是什么、轮廓不粘连，就通过。不要在这一步纠结“好不好看”。

---

### 三、先静后动：关键帧确认之前不做动画

**原则**：动画的基础是**一个站得住的静态关键帧**。如果静止状态下的比例、锚点、配色或轮廓有任何问题，做成动画只会把问题放大到每一帧。

具体做法：先用 `pixel_art`（或对应插件的静帧能力）做出一帧**“动作最舒展或最具代表性的姿势”** ，确认它在 1× 尺寸下的可读性、锚点是否精确落在底部中心、主体是否完全在画布内、透明背景边缘是否干净。这一帧通过后，再把它作为动画的基准帧，用 `pixel_animation` 或动效预设来生成其余帧。

DSH 的 `pixel_animation` 支持“显式帧”和“基础精灵 + 动效配方”两种模式，后者内置了 `bob`、`float`、`breathe`、`sway`、`shake`、`pulse`、`spin`、`orbit` 等预设。但**预设不应替代关键帧确认**：先用静帧把“身体比例、锚点、调色板”锁死，再用预设做节奏和幅度调整，返工成本最低。

---

### 四、每次只改一个变量

**原则**：一轮迭代只调整一个维度——**要么尺寸，要么调色板，要么光照，要么动作幅度，要么帧率**。同时改两个以上变量，一旦结果不对，你无法判断是哪个改动导致的。

这条原则在 DSH 的 Agent 工作流中尤其重要，因为 Agent 会忠实执行你描述的所有变更。如果你在一句话里同时说“放大到 48×48、换成 DB16 调色板、光照改成右上、帧率提到 12fps”，出问题后定位成本会成倍上升。

**推荐的迭代节奏**：

| 轮次 | 只改什么 | 保持不变 |
|---|---|---|
| 第 1 轮 | 轮廓 / 打形 | 尺寸、调色板、锚点 |
| 第 2 轮 | 底色 → 阴影 → 高光 | 轮廓、尺寸、调色板 |
| 第 3 轮 | 局部颜色或光照方向 | 其余全部 |
| 第 4 轮 | 动作幅度或帧率 | 尺寸、调色板、锚点 |

每次改完，在 DSH 的原生画布上用**洋葱皮**对比前后帧，或用 **1× 最近邻缩放**检查像素是否意外偏移或粘连。

### 五、导出前验收：逐项打勾，不通过不导出

导出不是“点一下按钮”，而是一次**结构性质检**。以下清单按优先级排列，建议在每次正式导出前逐项过一遍。

#### 5.1 尺寸与画布

- 每一帧的像素尺寸**严格等于**锁定规格，无任何一帧多出或缺少行列。
- 主体完全在画布边界内，**没有任何像素被裁切**，同时边缘留白不过大。
- 如果使用精灵表，确认**所有帧共用同一画布尺寸**，无帧偏移。

#### 5.2 透明与边缘

- 背景是**真正的透明通道**，不是白色或棋盘格“看起来像透明”。
- 放大到 8× 以上检查：边缘**没有半透明抗锯齿像素**，没有不属于调色板的杂色。
- 如果在引擎中测试，确认**边缘出血**是否出现——这是精灵表中帧与帧之间像素“渗色”的常见问题。

#### 5.3 调色板

- 所有颜色都来自锁定的调色板，**没有意外混入的近似色**。
- 色数不超过上限。DSH 的 craft report 会给出确定性的工艺评分，可以作为辅助参考，但不能替代人工检查。

#### 5.4 锚点与对齐

- 锚点坐标在**每一帧中完全一致**。角色类素材的锚点通常位于底部中心，道具类位于中心。
- 如果动画包含“落地”或“站立”动作，**脚底 / 接触面在每一帧中保持同一像素行**，不上下浮动。
- 精灵表 + JSON 导出时，JSON 中的 frame 矩形与 PNG 中的实际像素区域**一一对应**，无偏移。

#### 5.5 帧率、帧序与循环

- 帧率与锁定规格一致。如果目标引擎有特定帧率规范（例如某些动效管线以 24fps 为基准），在导出前确认换算无误。
- **帧序正确**：用播放预览完整过一遍，确认没有前后帧颠倒。
- 如果标注为循环，**首尾帧衔接无跳变**；可以单独把最后一帧和第一帧并排对比。
- GIF 导出的循环次数、每帧时长与规格一致。

#### 5.6 引擎侧快速测试

如果素材要进引擎，导出后在目标引擎中做一次最小化测试：导入 → 设置过滤模式为 **nearest / point** → 按目标尺寸播放 → 检查帧序、循环 timing 和缩放是否出现模糊或渗色。像素素材的“看起来不对”有相当比例来自引擎过滤设置，而非素材本身。

### 六、常见陷阱与规避

**陷阱一：在对话中途“顺手”改了规格。** 例如第 3 轮觉得 32×32 不够精细，直接说“改成 48×48”。这会导致此前所有帧的锚点、精灵表布局全部失效。如果确实需要换尺寸，把它当作**一次独立的重新开始**，而不是迭代中的一步。

**陷阱二：用放大后的视图判断细节。** 像素素材的验收基准永远是 **1×（实际游戏尺寸）** 。8× 或 12× 适合检查边缘和单像素，不适合判断“看起来是否成立”。

**陷阱三：动画预设替代了关键帧判断。** `bob` 或 `breathe` 预设可以让帧动起来，但如果基准静帧本身锚点偏了 1px，预设只会让每一帧都偏 1px。先静后动的意义正在于此。

**陷阱四：导出后不检查 JSON / Atlas。** 精灵表 PNG 看起来正确，不代表 JSON 中的 frame 坐标正确。打开 atlas JSON，抽 2–3 帧对照 PNG 的实际像素矩形，确认 `x / y / w / h` 无误。

---

### 七、一条贯穿始终的原则

DSH 的像素插件是为 Agent **确定性生成**而设计的：单字符网格、生成前校验、craft report、零运行时依赖。这意味着**你给出的约束越具体、越稳定，Agent 的产出就越接近“可直接用”**。手册中的四个原则——先小后大、先静后动、单变量迭代、导出前验收——本质上都是在帮 DSH 减少不确定性，把创作精力集中在真正需要判断的地方：**轮廓是否成立，动作是否可信，素材放进游戏里是否“对”**。

## 常用指令

### 一、万能指令公式

**静态素材：**
> 生成一个【素材类型】，尺寸【W×H】，【视角/朝向】，【风格/调色板】，主体是【具体描述】，【光照/轮廓要求】，透明背景，像素网格对齐，无抗锯齿，导出【PNG/精灵表】。

**动画素材：**
> 生成【动画名称】，尺寸【W×H】，【视角/朝向】，【帧数】帧，【帧率】fps，【循环/单次】播放，锚点固定在【底部中心/中心】，动作关键帧为【描述】，帧间保持轮廓和配色一致，透明背景，导出【GIF/精灵表+JSON】。

**通用负面约束（可附在末尾）：**
> 不要抗锯齿、不要模糊、不要渐变噪点、不要超出调色板、不要改变画布尺寸、不要添加无关背景。

---

### 二、静态像素画面模板

1. **角色立绘/精灵**

> 生成一个 32×32 的像素角色，正面视角，Q版比例，使用 PICO-8 调色板，主体是穿棕色斗篷的勇者，左上光源，深色硬轮廓，透明背景，像素网格对齐，导出 PNG。

2. **道具/图标**

> 生成一个 16×16 的像素道具图标，45°俯视，主体是一瓶红色生命药水，高光在左上，外轮廓 1px 深色，透明背景，限制 8 色以内，导出 PNG。

3. **场景地块**

> 生成一组 16×16 的像素地块，俯视角，包含草地、泥土、石板三种变体，统一 PICO-8 调色板，硬边无抗锯齿，可无缝拼接，导出精灵表 PNG。

4. **场景小图**

> 生成一个 64×64 的像素场景，侧视角，夜晚森林营地，中央有熄灭的木柴堆，冷色环境光加局部暖色火光，限制 16 色，透明背景可选，导出 PNG。

5. **UI 元素**

> 生成一套 8×8 像素 UI 图标，包含加号、减号、关闭、确认、返回，单色白描边，透明背景，像素网格对齐，导出精灵表 PNG 和 JSON。

6. **特效帧**

> 生成一个 32×32 的像素爆炸特效静帧，中心亮黄、边缘橙红、外圈深红，硬边色块，无模糊，透明背景，导出 PNG。

---

### 三、动画模板

7. **角色待机**

> 生成 32×32 像素角色待机动画，正面视角，4 帧，8fps，循环播放，锚点底部中心，动作只有轻微呼吸起伏和斗篷摆动，帧间轮廓一致，透明背景，导出 GIF 和精灵表。

8. **角色行走**

> 生成 32×32 像素角色四方向行走动画，每个方向 4 帧，8fps，循环，锚点底部中心，关键帧为左脚踏出、并拢、右脚踏出、并拢，保持头部高度稳定，透明背景，导出四方向精灵表和 JSON。

9. **角色攻击**

> 生成 48×48 像素角色挥剑攻击动画，侧面朝右，6 帧，12fps，单次播放，锚点底部中心，关键帧为蓄力、挥出、命中、收招，剑光用 2 帧亮色残影表现，透明背景，导出精灵表。

10. **火焰循环**

> 生成 32×32 像素木柴堆燃烧动画，侧视角，8 帧，10fps，无缝循环，火焰从底部木柴向上跳动，橙黄主色加少量白芯，帧间火苗轮廓自然变化但不跳变，透明背景，导出 GIF 和精灵表。

11. **道具循环**

> 生成 16×16 像素宝箱开启动画，4 帧，8fps，单次播放，关键帧为关闭、锁扣弹开、箱盖抬起、金光溢出，透明背景，导出 GIF 和精灵表。

12. **精灵表批量**

> 生成一个 128×32 的精灵表，包含 4 个 32×32 的火焰帧，横向排列，统一调色板和锚点，透明背景，同时导出 PNG 和 JSON Atlas，JSON 中每帧命名为 fire_0 到 fire_3。

---

### 四、修改与批量指令

13. **局部修改**

> 在现有画布上只修改【区域/图层】：把【对象】的【属性】改为【目标值】，其他像素、尺寸、调色板、锚点保持不变。

14. **批量变体**

> 基于当前角色生成 3 个配色变体：红、蓝、绿，只改主色和阴影色，轮廓和像素位置完全不变，分别导出 PNG。

15. **规格统一**

> 将当前所有帧统一为 32×32 画布，锚点底部中心，调色板限制为 16 色，透明背景，按原帧顺序导出精灵表和 JSON。
