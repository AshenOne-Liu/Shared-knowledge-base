# DSH 安装与环境配置

## 工具准备（DSH）

### 安装DSH

安装 DSH 桌面版。桌面版软件内置 Node.js、pnpm 和 Python，不依赖系统环境。

登录账号。

（如果要从外部调用 seepseek，才需要配置 API。使用 DSH 来开发软件就不需要。）
检查网页搜索与获取方式：插件-网页搜索与获取-选择deepseek API

### 安装必要插件

#### 应用商店 `dshmarket`

这是整个生态的入口。安装后 DSH 设置里会直接出现“插件市场”，可以搜索、一键安装、升级、卸载社区插件，还能备份还原配置。无论你后面想装什么，**第一步都是先把它装上**，否则每个插件都要手动查 npm 包名和安装命令。

#### 桌面通知 `dsh-notify-me`

长时间离开、后台执行的通知都会在前台发送。

#### 记忆工具`dsh-auto-memory`

#### 上下文压缩`billion-context`

#### 安全护栏

即使在工作区内，误删代码文件也很麻烦。DSH 社区有几个专门防止误删的安全插件，它们就像给围栏又加了道保险。（还没找到适合的）

## 工具准备（DSH 外部）

### 安装环境

> 安装方法见 `安装手册`。

#### 必要工具

**Node.js**：DSH Desktop 虽然自带运行环境，但是开发过程需要调用系统级的开发环境。所以，这个工具必须安装。

#### 可选工具

**包管理器 pnpm**：

- 和 Node.js 一样，DSH Desktop 自带的运行环境中也包含了 pnpm，但还是要根据开发需求安装系统级的开发环境。
- 插件开发和源码构建都依赖 pnpm。`dsh plugin` 等命令在底层会直接调用 pnpm，如果系统没有 pnpm，相关操作会报错。
- 非 Node.js 生态的软件：如果你开发的是纯 macOS 原生应用（使用 Swift/Xcode），或后端完全不涉及 JavaScript/TypeScript 的软件，那你的核心工具链里根本就不会出现 pnpm。

### 安装工具箱

> 安装方法见 `安装手册`。

**安装Flutter SDK：**

- 包含编译器、打包工具。后续 DSH 的 Shell 工具会调用这些命令。
- 在系统中安装，确保 Flutter 环境跑通。

### 安装外部工作台

**安装VS Code 等编辑器：**

- DSH 擅长“让 AI 替你写”，VS Code 擅长“让你自己看懂和微调”。对于零基础用户，看懂代码、在关键处做一点手动修改。

### 安装备份工具

**安装 GitHub Desktop。**

- 登录 GitHub 账号。
- 配置 Git 身份：GitHub Desktop 登录后通常会自动完成配置。

**安装 Git：**

- 需要在命令行用 git：或者未来打算使用 VS Code 等工具的集成终端，建议单独安装 Git。安装后，GitHub Desktop 通常也能自动识别并使用你安装的这个版本。

注意：在 Windows 中安装 Flutter SDK 依赖 Git for Windows。
