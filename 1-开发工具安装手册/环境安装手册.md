## Node 与 pnpm

针对你开发插件和独立软件的需求，**最稳妥的方案是使用版本管理器（NVM）来安装和切换 Node.js**，而不是直接用安装包。因为 DeepSeek Harness 有严格的版本限制，且开发过程可能需要你在不同版本间切换。

### DSH 对 Node 和 pnpm 的硬性要求

在动手之前，需要知道它对环境有明确约束：

- **Node.js 版本**：
  `package.json` 中的 `engines` 字段强制要求 **`^22.19.0 || >=24.0.0`**。这意味着你需要 **Node.js 22.19.0 及以上（22.x 系列），或者 24.0.0 及以上**的版本。`v22.14.0` 等较低版本会直接导致启动失败。**务必避免使用 Node 23、25 等奇数版本**，这些版本不被官方推荐，容易引发兼容性异常。
- **包管理器 pnpm**：
  插件开发和源码构建都依赖 **pnpm**。`dsh plugin` 等命令在底层会直接调用 pnpm，如果系统没有 pnpm，相关操作会报错。建议安装 **pnpm 11 或更高版本**。

### 安装/管理 Node.js（使用NVM）

使用 NVM 可以让你在保留其他项目所需 Node 版本的同时，为 DeepSeek Harness 专门准备一个符合要求的版本，互不干扰。

#### **Windows**

1. **卸载旧版 Node.js**：如果之前用安装包装过 Node.js，建议先从“控制面板”卸载，并清理环境变量中残留的 `nodejs` 或 `npm` 路径，避免冲突。
2. **下载并安装 `nvm-windows`**：从 [nvm-windows Releases](https://github.com/coreybutler/nvm-windows/releases) 页面下载 `nvm-setup.exe` 并安装。国内网络如果下载困难，可以尝试使用代理加速链接 `https://gh-proxy.com/https://github.com/coreybutler/nvm-windows/releases/download/v1.2.2/nvm-setup.exe`。
3. **（可选但建议）配置国内镜像**：为避免 `nvm install` 卡住，可以切换下载源。
   ```bash
   nvm node_mirror https://npmmirror.com/mirrors/node/
   nvm npm_mirror https://npmmirror.com/mirrors/npm/
   ```
4. **安装并启用指定版本**：打开**新的**终端（可能需要管理员权限），安装 22.x 系列的最新版本或 24.x 系列。
   ```bash
   # 安装 Node.js 22 系列的最新版
   nvm install 22
   # 启用该版本
   nvm use 22
   ```

#### **macOS / Linux**

1. 创建 ~/.zshrc 并追加 nvm 加载代码

   ```bash
   touch ~/.zshrc
   cat >> ~/.zshrc <<'EOF'

   # nvm
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
   [ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"
   EOF
   ```

2. 运行官方安装脚本。

   ```bash
   curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.3/install.sh | bash
   ```

3. 重开终端或输入代码使 nvm 生效。

   ```
   source ~/.zshrc
   ```
4. 验证nvm是否可用

   ```
   nvm --version
   ```
5. 安装并使用符合要求的Node.js版本。

   ```bash
   nvm install 24
   nvm use 24
   node -v
   ```

确认 node -v 输出为 v24.x.x，就满足 DeepSeek Harness 对 Node.js 的版本要求了。

### 安装 pnpm

Node.js 就绪后，全局安装 pnpm。你不需要纠结具体版本号，`npm` 会自动为你安装最新稳定版，通常能满足 `>=11` 的要求。

```bash
npm install -g pnpm
```

### 验证与关键提醒

安装完成后，在终端中逐项确认，确保环境完全合规：

```bash
node -v   # 输出应为 v22.19.0+ 或 v24.x.x
pnpm -v   # 输出应为 11.x 或更高
npx -v    # 确认 npx 可用，DeepSeek Harness 的部分工具依赖它
```

最后需要留意，DeepSeek Harness 目前处于**开发者预览阶段**，API 和兼容性可能继续调整。建议你固定使用某个具体的 Node 22.x 或 24.x 版本进行开发，并利用 NVM 随时切换回其他版本，以保持开发环境的稳定。

## Flutter SDK

安装 Flutter SDK 是开始开发的第一步。官方推荐的最佳实践是**通过 VS Code 安装**，这能自动完成大部分配置；当然，**手动下载安装**也同样可行。下面以手动安装为主线，分 Windows 和 macOS 两种情况说明。

---

### 安装前的准备

- **Windows 用户**：必须先安装 **Git for Windows**，Flutter 依赖它进行版本管理和包获取。
- **macOS 用户**：需要安装 **Xcode 命令行工具**，在终端执行 `xcode-select --install` 即可。这是编译和调试 Flutter 应用（尤其是 iOS 部分）的基础。

---

### 通过 VS Code 安装（推荐）

通过 VS Code 安装 Flutter SDK 是官方推荐的快捷方式，它能把下载 SDK、配置路径和验证环境整合在一个工具内完成。整个过程主要围绕 VS Code 的 **Flutter 扩展**和**命令面板**来操作。

#### 前提准备：安装 Git

Flutter 的包管理依赖 Git。在开始前，请确保系统已经安装了 Git：

- **Windows**：下载并安装 [Git for Windows](https://git-scm.com/downloads/win)。
- **macOS**：在终端中执行 `xcode-select --install` 来安装 Xcode 命令行工具，其中已包含 Git。

#### 1.安装 Flutter 扩展

1. 打开 VS Code。
2. 进入扩展视图（快捷键 `Ctrl+Shift+X` / `Cmd+Shift+X`）。
3. 搜索并安装 **Flutter** 扩展。安装 Flutter 扩展时，会**自动同时安装 Dart 扩展**，无需单独操作。

#### 2.通过命令面板触发 SDK 下载

扩展安装好后，通过以下步骤让 VS Code 自动获取 SDK：

1. 打开命令面板（`Ctrl+Shift+P` / `Cmd+Shift+P`）。
2. 输入 `Flutter`，选择 **`Flutter: New Project`** 命令。
3. 此时，VS Code 会提示你定位 Flutter SDK。选择 **`Download SDK`** 选项。
4. 随后会弹出对话框，让你选择 SDK 的安装位置。选择一个**全英文、无空格**的路径（例如 `C:\src\flutter` 或 `~/development/flutter`），然后点击 **`Clone Flutter`**。VS Code 会在后台使用 Git 克隆 Flutter SDK，并自动将路径写入设置中。

#### 3.如果 VS Code 未能自动找到 SDK

如果自动流程出现问题，或者你之前已经手动下载了 SDK，可以手动指定路径：

1. 打开命令面板。
2. 输入并选择 **`Flutter: Change SDK`**（部分版本可能显示为 `Flutter: Change SDK Path`）。
3. 在弹出的文件选择框中，**定位到你 Flutter SDK 的根目录**（即包含 `bin` 文件夹的那一层，例如 `C:\src\flutter`，而**不是** `C:\src\flutter\bin`）。
4. 点击确认后，路径会被保存。

你也可以通过设置界面手动编辑：打开设置（`Ctrl+,` / `Cmd+,`），搜索 `dart.flutterSdkPath`，在 `settings.json` 中添加或修改这一项，填入 SDK 的绝对路径。

#### 4.写入系统环境变量

> **VScode会提示是否加入到系统PATH中，选择加入即可，不用执行以下动作。**

通过 VS Code 安装 Flutter SDK 后，SDK 的 `bin` 目录路径会被记录在 VS Code 的配置（`dart.flutterSdkPath`）中。**DSH 的 Shell 工具继承的是系统环境变量 `PATH`**，因此，为了让 DSH 内的 Agent 也能调用 `flutter` 命令，你最好**同时将 Flutter 的 `bin` 目录添加到系统的 `PATH` 环境变量中**。这样，无论是在 VS Code 的内置终端，还是在 DSH 的工作区中，`flutter` 命令都能被正确识别，方便你在两个工具间无缝切换。

终端里找不到 `flutter` 命令，原因很直接：**VS Code 的 Flutter 扩展只是在自己的“内部环境”里记住了 SDK 的位置，并没有自动把它写入你系统终端（zsh）的 `PATH` 环境变量**。所以 VS Code 内部能用，外部终端却识别不了。

解决这个问题，只需要两步：找到 SDK 的实际路径，然后把它加入 zsh 的配置文件。

##### 1.找到 Flutter SDK 的安装路径

你需要找到包含 `bin` 文件夹的那一层 Flutter 目录的**绝对路径**。
假设你找到的路径是 `/Users/liuchen/development/flutter`，那么需要加入 `PATH` 的是它的 `bin` 子目录：`/Users/liuchen/development/flutter/bin`。

##### 2.将 `bin` 目录加入 zsh 的 `PATH`

macOS 官方 Flutter 文档推荐修改 **`~/.zprofile`** 文件。在终端中执行以下命令（**请将路径替换为你在第一步找到的真实路径**）：

```bash
echo 'export PATH="$HOME/development/flutter/bin:$PATH"' >> ~/.zprofile
```

> **说明**：如果你的 SDK 不在 `~/development/flutter`，请把命令中 `$HOME/development/flutter/bin` 的部分换成你的实际 `bin` 目录路径，例如 `export PATH="/Users/liuchen/sdk/flutter/bin:$PATH"`。

##### 3.让配置生效并验证

执行 `source` 命令使配置立即在当前终端会话中生效：

```bash
source ~/.zprofile
```

### 手动安装（不推荐）
#### Windows

**1. 下载并解压 SDK**
访问 Flutter 官方 SDK 归档页面，下载最新的 **stable** 版本压缩包（`.zip`）。**关键一步**：将压缩包解压到一个**全英文、无空格的路径**下，例如 `C:\src\flutter`。避免放在 `Program Files` 或带中文的目录，这能规避许多潜在的路径错误。

**2. 配置环境变量（将 Flutter 加入 PATH）**
这是让系统能在任何位置识别 `flutter` 命令的关键。

- 按下 `Windows + Pause` 键（或右键“此电脑” → “属性” → “高级系统设置”）打开环境变量窗口。
- 在“用户变量”区域找到 **`Path`**，双击编辑。
- 点击“新建”，输入你的 Flutter SDK 下 `bin` 目录的完整路径。如果你解压到了 `C:\src\flutter`，则输入：`C:\src\flutter\bin`。
- 连续点击“确定”保存所有窗口。

**3. 应用更改**
**关闭所有已打开的终端（CMD、PowerShell）和代码编辑器**，然后重新打开一个终端，环境变量才会生效。

---

#### macOS

**1. 配置环境变量（将 Flutter 加入 PATH）**
macOS 默认使用 Zsh，需要编辑 `~/.zprofile` 文件（如果不存在则创建）。

- 在终端中执行：`open -e ~/.zprofile`（用文本编辑器打开）。
- 在文件末尾添加一行，将 Flutter 的 `bin` 目录加入 PATH。假设你的路径是 `~/development/flutter`，则添加：

  ```bash
  export PATH="$HOME/development/flutter/bin:$PATH"
  ```
- 保存并关闭文件。然后执行 `source ~/.zprofile` 使配置立即生效。

**2. 安装 CocoaPods（为后续 iOS/macOS 开发）**
如果你的 Todo 应用未来会用到依赖原生代码的插件，CocoaPods 是必需的。可以通过 Homebrew 或 RubyGems 安装，具体参考 CocoaPods 官方指南。

---

### 验证安装

完成上述步骤后，打开一个**新的** VS Code 终端（`Ctrl+`  / `Cmd+`），运行：

```bash
flutter --version
```

如果正确显示版本号，说明 SDK 已就绪。你还可以运行 `flutter doctor` 来检查更详细的环境状态，但初期对于 Android/iOS 工具链的报错可以暂时忽略，你完全可以先在桌面端（Windows/macOS）开始开发 Todo 应用。

### 运行 Flutter 的环境诊断工具

```bash
flutter doctor -v
```

这个命令会详细检查你的开发环境，并列出所有依赖项的状态。**不要被红色的“✗”或警告吓到**，对于你的跨平台 Todo 项目，重点关注以下两项即可：

1. **Flutter**：应显示绿色的“✓”和正确的版本号。
2. **Android toolchain / Xcode**：这两项分别对应 Android 和 iOS 的开发环境。**初期可以先忽略它们的错误提示**，你完全可以先在 Windows 或 macOS 桌面上把 Todo 应用的核心功能（增删改查、本地数据库）跑通。等到需要打包到手机端时，再根据 `flutter doctor` 的提示去安装 Android Studio 或配置 Xcode 签名。

### 与 DSH 工作流的衔接

在系统终端里成功运行 `flutter doctor` 并看到 Flutter 项为绿色对勾后，就可以回到 DSH 桌面版，在你的工作区中让 Agent 调用 `flutter` 命令来创建项目、拉取依赖了。DSH 的 Shell 工具会继承你系统终端的环境变量，因此这里配置的 PATH 对它同样生效。
