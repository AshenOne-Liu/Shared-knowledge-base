# Markdown 使用说明

> 说明：本文中的“源码”是你在 `.md` 文件中输入的内容；“渲染效果”是在 Markdown 预览器中看到的效果。不同预览器对 Mermaid、任务列表、换行等支持略有差异。

## 1. 新建与预览

### 新建 Markdown 文档

打开 VSCode，按 `Ctrl+N` 新建文件，将内容粘贴进去，另存为 `.md` 格式。

### 原生查看预览

右键点击编辑区内容，选择“打开侧边预览”；

或按下快捷键 `Ctrl+K, V`（先按 `Ctrl+K`，松开后再按 `V`）。

对预览右键选择“在浏览器中打开”，再另存为 PDF 即可保存。

## 2. 标题

标题用于控制文章结构层级，最多 6 级。符号 `#` 和标题文字之间要有空格。

**源码：**

````markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
````

**渲染效果示意：**

- `# 一级标题`：显示为页面最大标题
- `## 二级标题`：显示为第二级标题
- `### 三级标题`：显示为第三级标题
- 依次类推，最多到六级

> 注意：Markdown 原生不支持标题自动序号。需要序号时请手动输入，如 `## 1. 安装说明`。

**我个人的使用规范：**

- 默认标题采用标准格式，最低级别标题采用加粗的形式。
  好处是符合我自己的word使用习惯。最低级别标题通常用来作为最基础的文字分段。统一格式会比较好看。不会出现一个一级标题下有一个孤零零的二级标题，或者都是最简单的“说明”文字，一个是二级标题，一个是五级标题。
  注意：直接加粗会触发markdownlint插件的格式检测错误（它会误以为这应该是个标准格式的标题），加一个冒号就可以解决。
- 标准markdown格式要求一个文件只允许有一个一级标题。我在默认情况下会遵守这个格式要求。但是在特定文档（比如复杂的交互手册）中，为了整合文件，可能会突破这个限制。

## 3. 段落与换行

段落之间用一个空行分隔。普通换行在部分预览器中会被合并为同一段；如需强制换行，可在行尾输入两个空格，或使用 `<br>`。

**源码：**

````markdown
这是第一段。

这是第二段。

这是第一行  
这是第二行，行尾有两个空格，强制换行。
````

**渲染效果：**

这是第一段。

这是第二段。

这是第一行
这是第二行，行尾有两个空格，强制换行。

## 4. 强调：粗体、斜体、删除线、行内代码

**源码：**

````markdown
**粗体**
*斜体*
***粗斜体***
~~删除线~~
`行内代码`
````

**渲染效果：**

**粗体**
*斜体*
***粗斜体***
~~删除线~~
`行内代码`

> 在序号之后直接使用加粗，渲染时会被认为是普通字符（即，没有加粗效果，而是直接显示`**XX**`。此时只需要在后面加上冒号即可。

## 5. 列表

### 有序列表

数字加点，后面加空格。

**源码：**

````markdown
1. 第一项
2. 第二项
3. 第三项
````

**渲染效果：**

1. 第一项
2. 第二项
3. 第三项

### 无序列表

使用 `-`、`*` 或 `+`，后面加空格。（DSH生成文档时习惯使用`*`，我的个人习惯是使用`-`。没有实质影响）

**源码：**

````markdown
- 项目一
- 项目二
  - 子项目
  - 子项目二
````

**渲染效果：**

- 项目一
- 项目二
  - 子项目
  - 子项目二

### 嵌套列表

子项通常缩进 2 个或 4 个空格。

**源码：**

````markdown
1. 第一项
   1. 子项一
   2. 子项二
2. 第二项
````

**渲染效果：**

1. 第一项
   1. 子项一
   2. 子项二
2. 第二项

## 6. 引用

使用 `>` 表示引用，支持嵌套。

**源码：**

````markdown
> 这里是一段引用文字。
>
> > 这里是嵌套引用。
````

**渲染效果：**

> 这里是一段引用文字。
>
>> 这里是嵌套引用。
>>

## 7. 代码

### 行内代码

用一对反引号包裹。

**源码：**

````markdown
请执行 `console.log("Hello")`。
````

**渲染效果：**

请执行 `console.log("Hello")`。

### 多行代码块

用三个反引号包裹，开头可写语言名用于语法高亮。

**源码：**

````markdown
```javascript
// 这里是 JavaScript 代码
console.log("Hello World");
```
````

**渲染效果：**

```javascript
// 这里是 JavaScript 代码
console.log("Hello World");
```

## 8. Mermaid 图表

需要预览器或插件支持 Mermaid。代码块语言名写 `mermaid`。

**源码：**

````markdown
```mermaid
graph LR
A[开始] --> B{结束}
```
````

**渲染效果：**

```mermaid
graph LR
A[开始] --> B{结束}
```

## 9. 链接与图片

**源码：**

````markdown
[OpenAI](https://openai.com)

![图片说明](图片路径.png)
````

**渲染效果：**

[OpenAI](https://openai.com)

图片语法渲染后会显示图片；如果图片路径无效，通常显示替代文字“图片说明”。本地图片建议使用相对路径，例如 `./images/demo.png`。

## 10. 表格

第二行是分隔行，用 `---` 分隔表头与内容。冒号控制对齐：

- `:---` 左对齐
- `---:` 右对齐
- `:---:` 居中

**源码：**

````markdown
| 姓名 | 年龄 | 说明 |
| :--- | ---: | :---: |
| 张三 | 18 | 左对齐 / 右对齐 / 居中 |
| 李四 | 20 | 示例 |
````

**渲染效果：**

| 姓名 | 年龄 |          说明          |
| :--- | ---: | :--------------------: |
| 张三 |   18 | 左对齐 / 右对齐 / 居中 |
| 李四 |   20 |          示例          |

## 13. 转义特殊符号

如果想让 `*`、`#`、`>` 等符号按普通文字显示，可在前面加反斜杠 `\`。

**源码：**

````markdown
\*不是斜体\*
\# 不是标题
````

**渲染效果：**

\*不是斜体\*
\# 不是标题

## 14. VSCode 实用插件与快捷键

### 原生预览

- 右键选择“打开侧边预览”
- 或按 `Ctrl+K, V`
- 预览中右键选择“在浏览器中打开”，再另存为 PDF

### Markdown Editor 插件

- 可直接编辑 Markdown 渲染页面，自带大纲
- Windows/Linux：`Ctrl+Alt+Shift+M` 快速启动
- macOS：`Command+Option+Shift+M` 快速启动
- `Command+Option+1/2/3/4/5` 设置标题层级
- 所见即所得模式可粘贴 Markdown 内容，但会被标记为纯文本代码块，建议在源代码中粘贴

### Markdown All in One 插件

- 「英文状态」下 `Ctrl+Shift+[` / `Ctrl+Shift+]` 可快速调整标题级别
- 需要在编辑页面活动时才生效；使用 Markdown Editor 编辑时，需要切换页面

### Outline Eclipse 插件

- 支持大纲拖拽排序
- 需要在编辑页面活动时才生效；使用 Markdown Editor 编辑时，需要切换页面

### markdownlint 插件-标题规则检测

该插件会检查并提示不符合规范的标题

可选修改：

1. 默认情况下一个markdown文档只允许有一个一级标题。可以通过在修改VS code全局设置来取消这一限制。
2. 默认情况下，markdown文档不建议使用文字相同的标题（即便是不同标题级别）。

修改方法：

1. 用快捷键 Ctrl + Shift + P (Windows/Linux) 或 Cmd + Shift + P (macOS) 打开命令面板，输入 Preferences: Open User Settings (JSON) 并选择。
2. 在打开的 settings.json 文件中，添加 markdownlint.config 配置块

配置块：关闭一级标题限制提醒：

```json
{
  "markdownlint.config": {
    "MD025": false
  }
}
```

配置块：关闭相同文字标题提醒：

```json
{
  "markdownlint.config": {
    "MD024": {
      "siblings_only": true
    }
  }
}
```

补充说明：

- 根据json语法，前面的最后一行代码尾部要添加一个逗号，所以正确的设置应该如下所示（如果根容器内是空的，直接填入就好）
- 如果已经有"markdownlint.config"，或者要添加多个同一键的内容，需要放在同一个键里面，否则会解析出错。除了最后一个值以外，前面的也要加逗号

  ```json
  {
      "editor.fontSize": 14,
      "markdownlint.config": {
          "MD025": false,
          "MD024": {
              "siblings_only": true
          }
      }
  }
  ```

### markdown文档+图片打包整理

使用外部工具「MD 行囊」（最贴合你的描述）
如果你不限定必须在 VS Code 内部完成，uTools 平台上的插件 “MD 行囊” 可能是最贴合你“大文件夹 + 图片子文件夹”这一结构需求的工具。

核心机制：它专为整理散落在不同目录的本地资源而设计。你只需选择一个 .md 文件，它就会扫描并收集其引用的所有本地图片、附件等，整理成一个独立的内容包，并且全程不修改原始文档。

完美的目录结构：它的 “分享文件夹” 导出模式，描述正是“多篇文档合并到一个目录，保留各自文件名，共用图片和附件目录”。这直接生成了你想要的最终结构：一个根目录（大文件夹），里面放着 Markdown 文件和一个公用的图片子目录。

适用场景：非常适合在需要将一份图文并茂的文档完整地归档、备份或发送给他人时使用，因为它能确保资源不丢失且路径正确。

## 15. 注意事项

1. Markdown 原生不支持标题自动序号。
2. 标题符号 `#`、列表符号 `-`、引用符号 `>` 后面通常要加空格。
3. 代码块的反引号必须成对出现，语言名紧跟在开头三个反引号后。
4. 表格前建议留一个空行。
5. 不同预览器对换行、Mermaid、任务列表的支持可能不同。
6. 粘贴 Markdown 源码时，优先在源代码模式中粘贴，避免被识别为纯文本代码块。
